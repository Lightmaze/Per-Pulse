# Per Pulse v0.1.0a29

Continue a file made in Home inside an independent Work, then bring the finished result back to the original conversation. This alpha packages [#311](https://github.com/Lightmaze/Per-Pulse/pull/311), merged after [v0.1.0a28](https://github.com/Lightmaze/Per-Pulse/releases/tag/v0.1.0a28).

## A Home file can become a Work's original source

1. In Home, complete a file-producing action through the existing Kernel file-approval or Undo workflow.
2. Open the finished file and choose **Add the full file to another page's draft**. Select an **existing** Work. The receiving draft keeps its previous text and gains the verified source material plus a navigable link to Home. Nothing is sent to the model until the user presses **Send**.
3. In that Work, continue the source file, produce the next artifact under the normal file-action boundary, and carry the selected result back Home. The original file identity, producer action and SHA-256 stay checkable across an SQLite service restart.

This extends the existing Work-to-Work file handoff to Home rather than introducing another material store, world or authority path. If a file no longer matches its original version, reopen the original file result before attaching it. [Installation and handoff steps](https://github.com/Lightmaze/Per-Pulse/blob/main/docs/install.md#continue-a-home-file-in-another-work) are included with the distribution.

The merged [#311](https://github.com/Lightmaze/Per-Pulse/pull/311) browser regression runs the Home → existing Work → revised file → Home → SQLite restart path, including genuine native source checks, file bytes and approvals. The model tool calls in that regression are explicitly authored synthetic HTTP responses. A real model's natural decision improvements remain subject to the provider, budget and independent-review conditions in [#51](https://github.com/Lightmaze/Per-Pulse/issues/51).

## Install or update

Requires Python 3.12 or later. Download `per_pulse-0.1.0a29-py3-none-any.whl` from this release's assets after publication.

Linux/macOS:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./per_pulse-0.1.0a29-py3-none-any.whl
per-pulse --example
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\per_pulse-0.1.0a29-py3-none-any.whl
.\.venv\Scripts\per-pulse.exe --example
```

Open **http://127.0.0.1:8000** to try the offline example without a provider. Stop the service and back up the complete data directory before upgrading a real workspace.

After merging, require a separate successful Verify on the exact main commit before a new tag and wheel, sdist and `SHA256SUMS` are published. Verify published digests and the installed-wheel browser journey. Do not reuse or overwrite v0.1.0a28 assets.
