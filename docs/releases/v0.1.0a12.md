# Per Pulse v0.1.0a12

This alpha makes the same persistent environment usable across Home and multiple focused Works. It follows [v0.1.0a11](https://github.com/Lightmaze/Per-Pulse/releases/tag/v0.1.0a11).

## What's new

- **Two Works can continue one real place.** Home or a Work visits a named native Habitat region. Work A can propose a file write and, after **Allow once** on that exact original Kernel action, create the physical object. Work B can read and append to it. Home can revisit it after restarting the service, with the last verified writer's original source and file-effect record (#181).
- **Read the entire evolving file.** When a regional observation exceeds 64,000 characters, `habitat_observe(read)` returns `nextOffset`, `totalChars` and `fullCurrentSha256`. Continue with `offset` and `expectedSha256` to read the rest of the same version; a modified file requires restarting at offset zero rather than stitching unrelated versions together (#242).
- **Keep working through a partial Home outage.** If Pulse's observation temporarily fails but the World has current Work information, its Work review action remains reachable. Unverified Pulse results stay unavailable (#241).

This uses the existing single World, Kernel, managed Habitat and SQLite ownership. Ordinary workspace file changes still have conditional Undo. **Habitat region changes do not yet have Undo and require explicit Allow once**, even when auto-apply is selected for ordinary file edits. Never replay an uncertain write.

## Install or update

Requires Python 3.12 or later. Download `per_pulse-0.1.0a12-py3-none-any.whl` from this release.

Linux / macOS:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./per_pulse-0.1.0a12-py3-none-any.whl
per-pulse --example
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\per_pulse-0.1.0a12-py3-none-any.whl
.\.venv\Scripts\per-pulse.exe --example
```

Open **http://127.0.0.1:8000**. Example mode is sample data and does not call a model. Stop the existing service and back up the complete data directory before upgrading the installed wheel. The existing World schema v13 remains in use. See [installation](https://github.com/Lightmaze/Per-Pulse/blob/main/docs/install.md) for model configuration, Windows setup and checksum verification.

## Verification and next step

Release requires native, Windows, Docker recovery and Chromium checks on the exact candidate, distribution/source verification, and clean Linux/Windows/macOS installs before publishing. The native regional journey uses real Kernel approvals, World/SQLite, filesystem effects and Chromium with explicitly synthetic HTTP model choices. It verifies the mechanism, not that a live model proactively returns to Habitat or uses prior experience to improve its next decision. That real-provider study remains separate.
