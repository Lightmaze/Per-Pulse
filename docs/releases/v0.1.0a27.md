# Per Pulse v0.1.0a27

Carry an earlier Work decision into the next task with its exact historical source instead of relying on a shortened Home conversation. This alpha packages four changes already merged after [v0.1.0a26](https://github.com/Lightmaze/Per-Pulse/releases/tag/v0.1.0a26).

## Complete the sourced Work journey

- **Cold-installed Work journey** ([#302](https://github.com/Lightmaze/Per-Pulse/pull/302)). The distribution's isolated-wheel Chromium check exercises a correction saved in Work A, a later Work B, an approved file artifact, a sourced Home return and restart. The browser, native World/Kernel, file action and installed wheel are real; the provider response is an explicit fixture.
- **Find earlier decisions** ([#303](https://github.com/Lightmaze/Per-Pulse/pull/303)). From Home, the native `work.inspect` tool searches an owned Work's message content or pages backward with `before_seq`, beyond the recent 12 messages. It returns original event IDs from the existing World/SQLite.
- **Read the actual match** ([#304](https://github.com/Lightmaze/Per-Pulse/pull/304)). Long historical messages yield a continuous exact source span around the query, with original character offsets and a truncation marker rather than an unrelated first 2,000 characters.
- **Send the verified quote onward** ([#305](https://github.com/Lightmaze/Per-Pulse/pull/305)). `work.create` and `work.send` accept the owned source Work ID, original event ID and verbatim excerpt. The World validates the source at preparation and delivery; source text remains attributed history rather than a new instruction, and file effects still follow their original approval/Undo boundary.

See the [Home-to-Work continuation instructions](https://github.com/Lightmaze/Per-Pulse/blob/main/docs/install.md#continue-from-an-earlier-work-decision). A configured model has access to this route; autonomous use of prior decisions and improvement in its final work are not established by these tests.

## Install or update

Requires Python 3.12 or later. After publication, download `per_pulse-0.1.0a27-py3-none-any.whl` from the new release assets.

Linux/macOS:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./per_pulse-0.1.0a27-py3-none-any.whl
per-pulse --example
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\per_pulse-0.1.0a27-py3-none-any.whl
.\.venv\Scripts\per-pulse.exe --example
```

Open **http://127.0.0.1:8000** for the offline example. Stop the service and back up the complete data directory before upgrading a real workspace.

## Release acceptance

Require full Native, Chromium, Windows and Docker CI for the precise release PR head, an equivalent wheel rebuilt from the source distribution, plus Linux/Windows/macOS cold-install checks. After merge, separately verify a successful main CI on the exact release commit before the existing workflow creates the new tag, wheel, sdist and `SHA256SUMS`. Confirm published assets and hashes. Existing tags and assets are never overwritten.

Automated model responses are explicit synthetic HTTP fixtures; they do not demonstrate real-model autonomous retrieval or improved task outcomes. That experiment remains gated under [#51](https://github.com/Lightmaze/Per-Pulse/issues/51).
