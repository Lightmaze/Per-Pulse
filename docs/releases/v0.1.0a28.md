# Per Pulse v0.1.0a28

Continue a real task in Work B with Work A's original decisions available directly, and return a selected result to Home with the historical evidence that informed it. This alpha packages three native changes merged after [v0.1.0a27](https://github.com/Lightmaze/Per-Pulse/releases/tag/v0.1.0a27).

## Work can now revisit its own history and return the evidence

- **Read across owned Works** ([#307](https://github.com/Lightmaze/Per-Pulse/pull/307)). In a focused Work, `work.list`, `work.search` and `work.inspect` can retrieve earlier Work history from the same continuing subject. Native Kernel ownership still prevents access to another subject and does not let a Work create or send another Work.
- **Discover a decision by its text** ([#308](https://github.com/Lightmaze/Per-Pulse/pull/308)). `work.find(query, before_seq?)` searches original admitted messages across owned Works when the earlier title or ID is unknown. It returns bounded exact source excerpts, Work/event IDs, source offsets and a history cursor from the existing World/SQLite.
- **Carry original evidence back to Home** ([#309](https://github.com/Lightmaze/Per-Pulse/pull/309)). A later Work's `work.report` can attach an exact earlier Work event and excerpt to its selected result. Native source ownership and verbatim text are checked both when the report is prepared and before durable delivery.

The [installation guide](https://github.com/Lightmaze/Per-Pulse/blob/main/docs/install.md#continue-from-an-earlier-work-decision) explains the Home → Work A → Work B → sourced Home route. Actual native regression covers a cold SQLite restart, earlier Work discovery, reading a real `notes.txt` file and returning verified source, with foreign-source and incomplete-reference rejection. Model tool choices in those tests are explicitly authored synthetic HTTP responses; natural autonomous model benefit is a separate question under [#51](https://github.com/Lightmaze/Per-Pulse/issues/51).

## Install or update

Requires Python 3.12 or later. Download `per_pulse-0.1.0a28-py3-none-any.whl` from this release's assets after publication.

Linux/macOS:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./per_pulse-0.1.0a28-py3-none-any.whl
per-pulse --example
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\per_pulse-0.1.0a28-py3-none-any.whl
.\.venv\Scripts\per-pulse.exe --example
```

Open **http://127.0.0.1:8000** for an offline example. Stop the service and back up the complete data directory before upgrading a real workspace.

## Release acceptance

Before merging the release candidate, require full Native, Chromium, Windows and Docker CI at the exact PR head; distribution-file checks, a byte-equivalent wheel rebuilt from the source distribution, and isolated Linux/Windows/macOS wheel installations. After merge, separately require a successful native main CI at the exact release commit before publishing a new tag and the wheel, sdist and `SHA256SUMS`. Confirm the published assets, their digests and cold-install evidence. Do not overwrite previously published tags or assets.
