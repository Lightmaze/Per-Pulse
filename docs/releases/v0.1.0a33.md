# Per Pulse v0.1.0a33

Continue a finished Work result into a **new** Work, carry revisions and longer corrections reliably, and bring the result Home without duplicating tasks when a network receipt is lost. This update collects the already merged [#324](https://github.com/Lightmaze/Per-Pulse/pull/324), [#325](https://github.com/Lightmaze/Per-Pulse/pull/325), [#326](https://github.com/Lightmaze/Per-Pulse/pull/326), [#327](https://github.com/Lightmaze/Per-Pulse/pull/327) and [#328](https://github.com/Lightmaze/Per-Pulse/pull/328) since [v0.1.0a32](https://github.com/Lightmaze/Per-Pulse/releases/tag/v0.1.0a32).

## Carry actual work forward

In a Work with a completed response, select its useful passage and choose **Use in another page**. Edit the excerpt and next instruction, then **Create a new page from this result** and name the Work. The new Work receives a source-attributed first message without copying the private history of the original Work. Continue the work, refresh or navigate Back; the saved source and unsent drafts remain in their original pages.

For sending the result to an existing Work or returning it Home, if the native World receives the message but the browser loses its HTTP success response, retry in the **same dialog**. The original CausalLedger admission and source link are reused instead of issuing a second model stimulus. Changing the submission requires a new request identity rather than silently replaying different content.

A later Work can continue paging through older shared Posture experiences even after another Work revises one. Explicit `posture.get` can read the complete current long lesson and decision shifts through versioned `detail.next` fragments. Private, revoked and stale revisions retain their original restrictions.

## Install or update

Python 3.12 or later. Stop Per Pulse and back up the entire workspace data directory before installing an update. Download `per_pulse-0.1.0a33-py3-none-any.whl` from this release when published.

Linux/macOS:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./per_pulse-0.1.0a33-py3-none-any.whl
per-pulse --example
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\per_pulse-0.1.0a33-py3-none-any.whl
.\.venv\Scripts\per-pulse.exe --example
```

Open **http://127.0.0.1:8000**. The example runs without a provider; actual model work requires a configured provider.

## Acceptance and evidence

The five product PRs were merged on the same main branch after independent PR/Push Native, Chromium, Windows and Docker checks. The release candidate must independently pass exact-head PR/Push Verify, wheel/sdist content checks, a wheel rebuilt from sdist, and cold installed-wheel checks on Linux, Windows and macOS. The installed Linux wheel also runs the sourced-correction → later Work → approved artifact → Home return → restart Chromium path. Work creation, retry and source checks use the real native World/Kernel/SQLite and explicitly synthetic model traffic. They do not establish that a real model spontaneously chooses or improves later work; the live-provider study remains [#51](https://github.com/Lightmaze/Per-Pulse/issues/51).

Publish only after the **exact merged main commit** has independent successful Verify. The release workflow must create a new immutable `v0.1.0a33` prerelease with wheel, sdist and `SHA256SUMS`; never overwrite `v0.1.0a32`.
