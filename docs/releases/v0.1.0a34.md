# Per Pulse v0.1.0a34

**Keep work moving safely across longer tasks, network interruptions, and file Undo.** This candidate packages the already merged [#330](https://github.com/Lightmaze/Per-Pulse/pull/330) through [#338](https://github.com/Lightmaze/Per-Pulse/pull/338) after [v0.1.0a33](https://github.com/Lightmaze/Per-Pulse/releases/tag/v0.1.0a33).

## Continue the task, not only its source

When a long Work begins with an earlier Work's selected result and supporting material, the pre-action expert and the main model's bounded history retain the **last actual task instruction** alongside a clearly marked incomplete source preview. If an earlier source-bearing message drops out of native context, the original source pointer is refreshed from the same World. A revised saved lesson is refreshed at the next native decision; a withdrawn lesson cannot silently become active again. Original messages remain in SQLite and can be read by their existing history tools. This is input availability, not a measured real-model quality improvement.

## Recover ordinary sends and returns

If the server accepts a Home or Work Send but its HTTP response is lost, retrying the original request recovers the same native input, not a second task. A selected result returned from Work to Home retains the original source event even if the network acknowledgement and subsequent source projection fail; another Work cannot take over that source claim on retry. Work drafts and original history stay independently owned.

## Keep file actions safe through Undo

A lost Undo response is reconciled against the **anchored native workspace**, not an external symlink path. If the original file-producing action is undone, that historical action remains withdrawn as a source to another Work, even when an unrelated writer recreates the same file bytes. The person can deliberately select the current file as a new source. Approvals, Undo and effect execution remain in the original Kernel; no uncertain file effect is replayed.

Transient SQLite lease-renewal contention no longer permanently stops an otherwise continuing World.

## Install or update

Python 3.12 or later. Stop the local service and back up the entire workspace data directory before updating. Download `per_pulse-0.1.0a34-py3-none-any.whl` from this release once published.

Linux/macOS:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install ./per_pulse-0.1.0a34-py3-none-any.whl
per-pulse --example
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .\per_pulse-0.1.0a34-py3-none-any.whl
.\.venv\Scripts\per-pulse.exe --example
```

Open **http://127.0.0.1:8000**. The example is model-free. Live tasks need a model configured separately.

## Acceptance contract

Publish only after **this exact release candidate** passes independent PR and Push Verify (Native/Chromium/Windows/Docker), and the merged `main` commit passes its own independent Verify. The release workflow builds a wheel and sdist, validates archive content and `SHA256SUMS`, rebuilds the wheel from sdist, then cold-installs it on Linux, Windows and macOS. Linux exercises a full sourced correction → next Work → actual approved file → Home return → restart Chromium flow against the isolated installed wheel. The CI model responses are explicitly synthetic HTTP fixtures; they cannot establish that a real model autonomously applies a past correction. That controlled real-provider evaluation still requires the authorization and independent reviewer described in [#51](https://github.com/Lightmaze/Per-Pulse/issues/51).

Never overwrite the existing `v0.1.0a33` tag or assets; use a new `v0.1.0a34` prerelease linked to the verified merge commit.
